# Provider fixtures

Recorded provider responses, one exchange per file, used by tests and by `PROVIDER_MODE=fixture`
(the default), so the API runs with no provider credentials.

| Directory | Provider |
|---|---|
| `duffel/` | Duffel flights (`/air/offer_requests`) and stays (`/stays/search`) |
| `viator/` | Viator destinations, tags and `/products/search` |
| `ecb/` | ECB daily FX reference rates |

## How matching works

A file's name is a hash of the request's method, URL and body **with dates removed**. Request
headers, and so API keys, are never part of the key and never written. On replay:

- every date in the response is shifted by the offset of the closest request date, so one
  recording serves any travel dates (outbound times follow the departure date, return times
  follow the return date);
- Duffel offer and search-result IDs (`off_…`, `srr_…`) get the requested dates appended, so
  replays for different date pairs don't share IDs.

Prices are replayed as recorded. A hotel stay recorded for 7 nights keeps its 7-night total
when replayed for a 5-night trip, so treat fixture-mode prices as illustrative.

A request with no matching file gets a 404 (a `NOT_FOUND` degraded category) and a log line
naming the missing request.

## Current contents: synthetic

Every file here is marked `"synthetic": true`. They were generated by
`npm run fixtures:synth -w @travellite/api`, which runs the real adapters against fake
providers (`apps/api/scripts/synthetic.ts`) that answer in each API's documented wire format.
Viator destination IDs (`90000+`) are made up.

Coverage:

| Case | Where |
|---|---|
| 12 catalog cities, flights from JFK, SFO, LAX and ORD, 1–2 travelers | all |
| Malformed offer (dropped and counted) | one per flight response |
| Non-USD prices (converted with ECB rates) | London hotels (GBP), Tokyo hotels (JPY) |
| Budget breach | Reykjavik and Tokyo are priced ~2× Lisbon |
| Degraded category | Cancun activities return 503 |
| No flights | ORD → REK |
| Invalid IATA (422) | origin `ZZZ` |
| Rate limited (429, retry-after 1 s) | origin `QRL`; test city Ratelimitville |
| No availability / no products | test city Emptyville |
| Rejected hotel location (422) | test city Nowhere |

## Recording real responses

```bash
DUFFEL_ACCESS_TOKEN=duffel_test_… VIATOR_API_KEY=… \
  npm run fixtures:record -w @travellite/api -- JFK 2027-02-10 2027-02-17 2
```

This records flights, hotels and activities for every catalog city into `fixtures/recorded/`.
Fixture mode replays a recording when one matches and falls back to the synthetic files here;
tests only use the synthetic files, so recording never changes test results.

- Only successful responses are recorded. Errors (a rejected key, a feature not enabled for the
  account) are listed at the end of the run and leave existing fixtures alone.
- `fixtures/recorded/` is gitignored: real responses are large (Duffel returns hundreds of
  offers per search) and Viator product URLs carry your affiliate ID.
